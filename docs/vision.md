# Vision: Computing Commons as Recitation

## Core idea

The Computing Commons is the shared recitation layer underneath the SWOSU computing curriculum.

It exists so students do not have to relearn the same common tools, professional habits, and computing workflows separately in every course.

> **Learn the common craft once. Practice it everywhere.**

## What the student should feel

The Commons should not feel like a seventh course competing for attention.

A student should think:

- “CS1 is where I learn programming.”
- “DSCT is where I learn discrete structures and disciplined reasoning.”
- “Architecture is where I learn how machines behave.”
- “Software Engineering is where I learn to build software systems with other people.”
- “Machine Learning is where I learn models, data, evaluation, and limits.”
- “Computing Commons is the workshop where I learn the shared tools and habits I use in all of them.”

## Three operating modes

### 1. Required runway

Two common semester-entry experiences should be easy to find and intentionally shared:

- **Success Foundations / Semester Kickoff**
- **Build and Verify Your Local AI Lab**

These establish belonging, navigation, help-seeking, evidence habits, and a working local technical foundation.

### 2. Recitation toolbox

After the runway, the Commons becomes a reusable toolbox rather than a fixed weekly march.

Candidate shared recitations include:

- containers and repeatable environments;
- LaTeX and evidence-oriented documentation;
- Work First;
- Linux command-line inspection and profiling;
- source-code management with Git;
- common AI verification/accountability;
- professional workflow and career foundations.

Home courses call these recitations when needed.

### 3. Shared reunion

The semester can reunite the disciplines around a common **Farkle + Machine Learning** experience.

That shared phenomenon supports different disciplinary lenses:

- CS1: simulation and code;
- CS2: design and implementation quality;
- DSCT: probability, uncertainty, and reasoning;
- Computer Architecture: profiling, CPU/GPU behavior, scaling, and machine evidence;
- Software Engineering: system structure, testing, reproducibility, and collaboration;
- Machine Learning: model design, training, evaluation, and limitations.

Computer Architecture is especially well positioned as the technical bridge for the shared finale because it can expose what the machine is actually doing underneath the abstractions.

## Recitation hours

A portion of instructor office-hour capacity may become **Computing Recitation Hours**.

The purpose is a common support space where students can bring Local AI, Git, Linux, container, LaTeX, documentation, or workflow problems without first having to determine which course “owns” the problem.

Exact scheduling remains an operational decision and should be reconciled with the canonical office-hours source before publication.

## Design promise

The Commons succeeds only if it reduces overall cognitive and administrative load.

When a common lesson is centralized, the intended follow-up is to reduce duplicated copies, duplicated instructions, and duplicated grading in home courses.
