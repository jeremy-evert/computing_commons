# SWOSU Computing Commons

The **SWOSU Computing Commons** is the shared recitation and apprenticeship layer for SWOSU computing students.

Its purpose is simple:

> **Learn the common craft once. Practice it everywhere.**

The individual course repositories remain responsible for their disciplines. The Commons owns the shared skills, habits, tools, professional development, and recurring experiences that should not be duplicated across Computer Science I, Computer Science II, Discrete Structures & Critical Thinking, Computer Architecture, Software Engineering, and Machine Learning.

## What belongs here

The Commons is the natural home for shared experiences such as:

- Success Foundations / Semester Kickoff;
- AI Fluency;
- Professional Minds;
- building and verifying a Local AI Lab;
- containers and reproducible environments;
- LaTeX and evidence-oriented documentation;
- the Work First principle;
- Linux command-line inspection and profiling;
- Git / source-code management;
- common AI accountability and verification habits;
- professional-pathway foundations;
- the shared Farkle + Machine Learning finale.

Course-specific applications remain in the course repositories. For example, the Commons may teach Git once, while CS1 uses Git to protect a Python project, Architecture uses it to preserve investigation evidence, and Software Engineering uses it as part of a collaborative development workflow.

## Student model

The Commons should feel like a **shared computing recitation/workshop**, not a seventh academic course.

Students take their normal academic courses. Those courses point into the Commons when they need a common capability. Recitation hours provide a shared place to get help with those capabilities regardless of which computing course sent the student there.

## Progressive levels

The long-term progression is course-targeted but student-owned:

1. **Level 1 — CS1 target:** become a capable computing student.
2. **Level 2 — CS2 target:** become a capable computing practitioner.
3. **Level 3 — DSCT target:** strengthen judgment, evidence, uncertainty, and critical reasoning.
4. **Level 4 — Software Engineering target:** teamwork, systems, review, change, and professional engineering workflow.
5. **Level 5 — Machine Learning target:** understand models, data, evaluation, limitations, and responsible AI at a deeper level.

Computer Architecture acts as a cross-cutting technical bridge, especially for Linux inspection, profiling, CPU/GPU behavior, local-model performance, containers, and the shared Farkle + Machine Learning finale.

**Progressive-release rule:** when a student is asked to take Level N, Levels 1 through N should be available. Earlier levels remain open for review and recovery rather than disappearing behind the student.

## Fall 2026 posture

Fall 2026 is a soft-launch semester for the Commons. The preferred current pattern is:

- shared activities may have due dates and completion tracking;
- activities may be represented as **0-point assignments** while the architecture is being proven;
- strong evidence, useful troubleshooting, excellent verification, or other exceptional work may earn bonus credit in the home course;
- avoid rebuilding every production gradebook merely to test the Commons seam.

## Repository boundaries

- `computing_commons` owns the shared curriculum and its intended Commons delivery model.
- `swosu_cs_curriculum` owns the cross-course curriculum map and decisions about where shared material belongs.
- individual course repositories own disciplinary curriculum and course-specific wrappers/applications.
- Canvas is a delivery surface, not the source of truth for curriculum design.

## Current design principle

Every addition to the Commons should make the overall student/instructor system simpler. If a shared lesson moves here, duplicated copies and duplicated grading elsewhere should eventually shrink.

> **One common source. One common delivery surface. One completion event for genuinely common work. Many disciplinary applications.**
